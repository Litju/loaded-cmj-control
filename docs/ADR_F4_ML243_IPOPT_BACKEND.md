# ADR F4 / ML-243: Offline Ipopt Backend Adapter

Status: accepted for ML-243 qualification only

## Decision

`src/loaded_cmj/oracle/ipopt_backend.py` is the single offline solver owner.
It adapts one `DirectMultipleShootingProblem` directly to `cyipopt.Problem`.
The adapter consumes the problem's variable and constraint counts, bounds,
constraint values, Jacobian structure, and Jacobian values. It does not own
plant dynamics, constraint equations, derivative assembly, state geometry, or
scorer semantics.

The pinned backend is cyipopt 1.7.0 over official Ipopt 3.14.19 built with
MUMPS 5.8.2 as the one sparse linear solver. The adapter uses raw sparse
row/column/value callbacks in the exact ML-242 order. It never constructs a
dense Jacobian and is imported only at the offline solver boundary.

## Frozen numerical contract

- Hessian: `hessian_approximation=limited-memory`; no Hessian callback or
  finite-difference Hessian is implemented.
- Linear solver: `linear_solver=mumps`.
- Internal scaling: Ipopt `gradient-based`, objective scale `1.0`; physical
  scales remain ML-240/242 authority.
- Stopping: `tol=1e-7`, `constr_viol_tol=1e-7`, `dual_inf_tol=1e-6`,
  `compl_inf_tol=1e-6`, `acceptable_tol=1e-6`, `acceptable_iter=3`.
- Budget: one deterministic attempt, at most 100 Ipopt iterations, 30 seconds
  CPU time, with callback counts recorded by the adapter.
- Derivative checking is a synthetic-fixture diagnostic only. It is not run
  across hybrid contact kinks or qacc qualified-zero directions.

The qacc state columns remain present. Incoming columns 111:132 (1-based
contract notation) retain the ML-241 qualified-zero disposition and its
`1e-7` translation/rotation error bounds. No artificial diagonal or
regularization is added.

## Physical and scope guards

The unresolved `E3_E4_REVERSAL` Phase-I scale is rejected deterministically;
the adapter never substitutes a numerical normalization. No E3-to-E4 solve,
jump oracle, performance objective, or R025 execution is part of ML-243.

The short same-Plant backend fixture uses an exact S3 reference generated by
`step_5ms`. Its test-only Jacobian certificate is the existing ML-242
qualification-only exact-transition certificate replayed at the reference
point, with frozen ML-241 metadata. This keeps the physical constraint
callback owned by `DirectMultipleShootingProblem` and avoids adding a second
plant or derivative implementation. Production ML-241 derivative ownership
is unchanged.

cyipopt/Ipopt are offline oracle/development dependencies. Public runtime,
simulation, policy-worker, and release-replay imports do not require them.
